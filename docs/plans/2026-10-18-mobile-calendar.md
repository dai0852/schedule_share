# カレンダー中心の閲覧画面

## 合意した表示
- 全端末で月表示を初期表示にする。760px以下は画面幅内の月＋選択日の予定一覧。
- PCは各日に最大3件の予定を表示し、日付／ほか件数で選択日の全件を確認できる。担当者表の切替も残す。
- 同じ担当者のGoogle・Microsoft・旧Teams予定は同じ色でまとめ、元の区別は詳細に残す。重複排除しない。
- カレンダー／一覧の後に、初期閉じの担当者選択・その他操作のアコーディオンを置く。

## 実装順序
1. 担当者IDから安定した配色を提供する共通ヘルパーを追加。
2. 月表示の日付選択・件数・色、独立した日別一覧、既存担当者表の配色を実装。
3. ScheduleAppの表示月と選択日を分離し、初期月表示・モバイル切替・補助操作の配置を変更。
4. レスポンシブCSSと操作／競合テストを更新し、PROJECT.mdの現行方針を更新。

## 操作と境界
- 初期選択は今日。同月内の日付選択と担当者選択は再取得しない。
- 月送りでは移動先の1日、今月なら今日を選択。月外の日付選択はその月へ移動。
- スマホ幅へ縮めた際は担当者表から月へ戻す。
- 終日先頭・開始時刻順、日またぎは継続表示。本文・参加者・会議URLは表示しない。
- API・NormalizedEvent・同期・認証は変更しない。既存のユーザー変更を保持する。

## 検証
- 月／年の境界、今日、月外選択、担当者選択・全解除、空・多数・重複・終日・日またぎ。
- 古い応答とログアウト後のデータを表示しない既存保護を維持。
- 320／375／430pxとPCで横はみ出し・折りたたみ・幅変更・長文を確認。
- npm test、npx tsc --noEmit、npm run build。commit・push・公開は含まない。

## 統合確認での補足
- 月表示がAPIの1回1000件を超える場合に備え、月取得が500応答なら最大6週へ分割して取得する。各応答の件数・byte・構造検証を維持し、全週成功時だけ表示する。境界をまたぐ同一eventIdだけ統合する。
- 月カードも日またぎを当日の時刻・継続方向で表示する。
